### CON-ARCH-001 — X3 interlocked placement clearance for 3D-printed housing

| Field | Value |
| --- | --- |
| Type | constraint |
| Target | kc2-x3 |
| Status | verified |
| Priority | high |
| Tags | kc2 x3 mechanical housing magnet |
| Risk | high |
| Stability | stable |
| Verification Method | Board-coordinate render and kc2-pcb-preflight regression check. |
| GitHub Issue | - |
| Related Docs | docs/spec.md, docs/spec/20.kc2-no-stabilizer-layout.md |

#### Requirement

KC2 X3 shall define an interlocked joined-placement clearance between the left and right PCB Edge.Cuts so the right-side `Y`/`H` protrusion can enter the left-side `T`/`G` recess while the halves can still be used with a 3D-printed bottom housing and magnetic alignment without physical binding. The right-side `Y`/`H` protrusion may locally relieve its horizontal ledges by 0.8 mm while preserving the vertical protrusion face at the 3.6 mm X3 inner-edge margin.

#### Rationale

3D-printed bottom housings can swell or print oversized, and magnets add alignment tolerance. A zero-clearance joined reference is too tight for physical assembly, but a pure bounding-box gap wastes the available T/G and Y/H interlock geometry.

#### Acceptance Criteria

- [x] AC-1: Joined visual and mechanical reference render uses interlocked placement with 1.0 mm minimum Edge.Cuts clearance between the left and right PCBs.
- [x] AC-2: Specification allows 0.8-1.2 mm practical interlocked joined-placement clearance and treats 1.0 mm as the default.
- [x] AC-3: PCB electrical clearance and routing safety are not reduced below the X3 fabrication gate by this placement-clearance change, including the local right `Y`/`H` horizontal ledge relief.

### CON-ARCH-002 — X3 compact controller tab without PCB battery pads

| Field | Value |
| --- | --- |
| Type | constraint |
| Target | kc2-x3 |
| Status | verified |
| Priority | high |
| Tags | kc2 x3 controller compact battery reset |
| Risk | high |
| Stability | stable |
| Verification Method | KiCad Python geometry/power verifier, connectivity verifier, KiCad CLI DRC, kc2-pcb-preflight, fabrication ZIP manifest inspection, and sub-agent review. |
| GitHub Issue | - |
| Related Docs | docs/spec.md, docs/spec/20.kc2-no-stabilizer-layout.md |

#### Requirement

KC2 X3 shall remove the carrier-PCB battery/direct-solder power pad footprint from both halves, route no battery power nets on the PCB carrier, shrink each controller protrusion tab to fit tightly around the nice!nano v2 socket, antenna keepout, USB-C access, and reset tact switch, keep the reset tact switch on the antenna-side controller-tab edge where it remains pressable without entering the nice!nano socket or TW301525 battery reference area, and provide a non-plated battery-lead pass-through slot below the nice!nano v2 B+/B- top-pin area for an optional bottom-side cable exit.

#### Rationale

The previous PCB placed four exposed battery hand-solder pads beside the nice!nano socket, which widened the controller protrusion. Removing those carrier pads allows a tighter controller tab, but it changes the power assembly assumption: the Li-Po leads must be soldered directly to the nice!nano v2 B+/B- pads off the carrier PCB, so the carrier PCB must not contain stale battery nets or exposed power pads.

#### Acceptance Criteria

- [x] AC-1: Both left and right main KiCad boards contain no J_PWR1 footprint, no BAT+/BAT- carrier nets, and no NN_B+/NN_B- carrier pads or traces.

#### Requirement

KC2 X3 shall remove all dedicated M2 screw mounting holes from both PCB halves, use 1.6 mm PCB thickness, support an FDM PLA+ lower housing that primarily captures the PCB by printed ledges/rails rather than adhesive, add nine evenly distributed 3.0 mm NPTH registration and optional M2 clearance holes per half between key switch areas, shift the middle support holes toward the anti-flex center zones, visibly label the support holes as H1-H9, and retreat the PCB Edge.Cuts as far as practical while preserving enough rail land for the printed housing. Each corresponding lower-housing support post shall provide a centered 1.60 mm blind pilot bore for optional M2 self-tapping retention and a 2.55 mm registration peg for PLA print-expansion clearance. The lower housing shall have no front-to-rear slope: its exterior bottom, interior floor top, PCB support plane, wall top, and post/peg tops shall be parallel. The interior shall reserve 2.60 mm below the PCB, comprising the Kailh CPG135001S30 Choc V1 hot-swap socket's 2.20 mm body envelope plus 0.40 mm assembly and FDM tolerance, while retaining a 1.20 mm closed floor for a 3.80 mm total PCB support height. The interior wall shall clear every extracted bottom-side socket body and SMD-pad envelope by at least 0.30 mm laterally. The pilot bore shall open at the peg top and terminate at the flat floor top without penetrating the exterior bottom. Every printable housing STL shall fit within a 150 mm x 150 mm x 150 mm build envelope. The right housing shall therefore be exported as exactly two watertight single-solid STL parts separated by a post-avoiding zigzag glue seam. Each right mating face shall be recessed 0.20 mm from the nominal seam, producing a 0.40 mm nominal assembled gap for PLA expansion and adhesive.

#### Rationale

The user wants the X3 keyboard to remain thinner and visually tighter than the original dedicated M2 screw-fixed version while allowing optional screw retention when rail capture alone is insufficient. Dedicated screw holes and wide perimeter land should remain removed where possible, while the 3.0 mm registration holes, reduced-diameter printed pegs, and blind pilot bores provide repeatable registration, PLA tolerance, and an optional serviceable mechanical fastener path. A sloped floor adds material without increasing bottom-component clearance because the PCB support plane follows the same slope. A flat 3.80 mm support height preserves explicit clearance for the bottom-side Choc sockets and smaller SOD-123 components while removing the unnecessary rear thickness. The 193 mm-wide assembled right housing exceeds the user's 150 mm print-bed axis, so two printable parts are required. A zigzag seam increases the minimum floor bonding length over a straight cut, while the requested 0.20 mm setback on each face prevents PLA expansion from forcing the halves out of alignment.

#### Requirement

KC2 X3 V2 shall provide mutually exclusive assembly modes at every switch position: Kailh Choc V2/PG1353-class low-profile switches are supported only through a bottom-side Choc hot-swap socket, and Cherry MX-style 5-pin PCB-mount switches are supported only through direct-solder through-hole pads. The switch footprint shall not support Kailh Choc V1/PG1350 switches, Choc V2 direct-solder assembly, or MX hot-swap assembly. The board shall use the fixed 70-key stabilizer-free v5 layout defined in docs/spec/20.kc2-no-stabilizer-layout.md, with 31 left keys and 39 right keys, no key wider than 1.75U, and mutually compatible Choc V2 and MX placement geometry. Missing nonstandard keycaps may be produced as target-specific 3D-printed keycaps and are not a reason to enlarge a key beyond 1.75U or add stabilizers.

Every switch-matrix diode shall be the exact Jingdao Microelectronics `ES1B` sold as LCSC `C437840` and Eleparts goods number `9475342`, mounted on the PCB bottom with the manufacturer's recommended two `1.80 mm x 1.80 mm` SMA lands separated by `2.40 mm`. Pin/pad `1` is the cathode and shall connect to the row net; pin/pad `2` is the anode and shall connect to the per-key switch net. Bottom-side mirrored assembly documentation shall show the cathode band pointing to pad `1`. The BOM shall lock manufacturer, MPN, LCSC number, Eleparts number, package, and polarity rather than treating the generic `ES1B` name as sufficient identity.

#### Rationale

The user has Kailh Deep Sea-class switches and wants the next board revision to support Choc V2 low-profile socket assembly while retaining an MX direct-solder fallback. The current X3 board uses a Choc V1/PG1350-focused footprint and cannot be salvaged for Choc V2 by drilling because a 5.0 mm Choc V2 center hole collides with existing routing. Dropping Choc V1 support reduces footprint ambiguity and lets the next revision focus on the two intended assembly modes.

The user validated the general hand position on an existing Choc V1 build and selected the revised 70-key v5 arrangement after reviewing and physically reasoning about the earlier v4 layout. The inner 1.5U Enter remains the primary Enter because the previous outer-primary position was uncomfortable in actual use. On the left, the former standalone Fn switch is removed, its width is split equally between two 1.75U Space keys, the former Win position becomes Fn, and simultaneous Alt+Fn produces Win/LGUI. The two left Shift widths are exchanged so the outer key is 1U and the inner key is 1.25U. Nonstandard keycap availability is not a layout blocker because missing keycaps can be 3D printed, but the physical design remains stabilizer-free and caps every key at 1.75U.

The user's V1 assembly exposed two additional physical-footprint failures that must not recur: the carrier footprint used the nice!nano board width instead of the center-to-center spacing between its two socket-pin rows, and diode pads were too close to unused hybrid-switch holes and socket geometry for practical hand soldering. The user rejected the small SOD-123 diode as unreasonably difficult to solder by hand and selected the larger Jingdao ES1B SMA part after review. V2 therefore treats the controller row spacing, exact diode identity and polarity, diode-to-switch clearance, and solder-tool envelope as fabrication gates rather than relying on nominal pin pitch or ordinary electrical DRC alone.

#### Research / Analysis

- Local `third_party/key-switches.pretty` contains MX/Choc hybrid reference footprints, but the available hot-swap hybrid includes Choc V1 support and MX hot-swap geometry that this requirement explicitly excludes.
- Current X3 Choc V1 routing is not a reusable basis for drilled Choc V2 conversion: previous geometry analysis found that enlarging the center hole to 5.0 mm would intersect existing copper.
- Current promoted `hardware/kicad/kc2_left/`, `hardware/kicad/kc2_right/`, fabrication ZIPs, housing manifest, and `kc2_generation_manifest.json` remain verified X3 artifacts with the existing Choc V1-focused footprint. They are not V2 implementation evidence and must not be treated as orderable V2 outputs.
- Eleparts goods `9475342` is Jingdao Microelectronics `ES1B`, also cataloged by LCSC as `C437840`: SMA, 100 V, 1 A, `35 ns` reverse recovery, and pin `1` cathode / pin `2` anode. The official package maximum is `5.20 mm x 2.70 mm x 2.20 mm`, and the recommended land diagram is two `1.80 mm x 1.80 mm` pads separated by `2.40 mm`. Sources: [Eleparts 9475342](https://www.eleparts.co.kr/goods/view?no=9475342), [LCSC C437840](https://www.lcsc.com/product-detail/C437840.html), [Jingdao ES1A-ES1J datasheet](https://www.es.co.th/Schemetic/PDF/ES1A-ES1J_JD.PDF).
- Three independent reviews on 2026-08-24 agreed that the part is electrically and polarity compatible but is not a drop-in replacement for the existing SOD-123 footprint. A temporary same-center manufacturer-land substitution produced 45 left and 47 right KiCad DRC violations, while the generic KiCad SMA handsolder footprint produced 114 left and 82 right violations. A route-independent `0.25 mm` placement search found mechanically feasible positions for all 70 parts, so a fresh footprint, placement, routing, housing, and verification cycle is justified.
- ES1B's `35 ns` reverse recovery is negligible relative to keyboard scan timing, but its typical `15 pF` junction capacitance and low-current forward-voltage behavior are not equivalent to the previous small-signal diode. The pinned firmware records zero additional wait before input reads or between driven columns. Before order approval, a populated coupon or first article shall verify 3.0/3.3 V row-high margin and false-key-free scanning for worst-case maximum same-row and same-column multi-key patterns with that unchanged zero-wait baseline; firmware scan delays shall not be changed before the baseline is recorded.

#### Requirement

The KC2 KiCad workflow shall expose Konnect MCP operations that safely edit the net assignment of exact pads in placed PCB footprints, list board-level graphic and text items with stable UUID selectors, and atomically delete only explicitly selected board-level graphic or text items without directly rewriting .kicad_pcb text. #### Rationale

CON-ARCH-007 requires new BAT+/NN_B+/GND pad assignments and removal of historical TW301525 B.Fab graphics, but installed Konnect v0.9.0 exposes neither capability. OPS-ARCH-003 is retained because Reference-field geometry has different selectors and invariants.

#### Acceptance Criteria
