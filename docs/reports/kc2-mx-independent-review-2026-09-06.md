# KC2 MX revision independent review — 2026-09-06

Scope: `CON-ARCH-004`, `CON-ARCH-006`, `CON-ARCH-007`, `REL-ARCH-001`.
This is review evidence, not an alternate requirements source or fabrication approval.
Other agents were modifying routing and housing concurrently; findings describe the
inspected state and require final rerun after those edits.

## Result

**Not order-ready.** Physical evidence has no source bindings and all four bundles
in `hardware/kicad/kc2_physical_evidence.json` have empty artifacts/metrics. A
small-volume first build being the final build does not establish physical fit.
No fabrication outputs were generated by this review.

## Findings and remediation

1. **Saved solder-mask regression:** a fresh, standalone KiCad Python process
   loading the canonical left PCB found both mask layers absent on every U1,
   J_BAT1 and SW_PWR1 PTH pad. Existing same-process pad tests were misleading:
   the parent reproduced this with a new failing fresh-process test. Correct
   serialization and inspect freshly reloaded boards and plotted apertures.
   This is actual solderability, not merely copper-area sizing.
2. **Stale battery contract:** generator/manifest and main verifier still used
   0.72 mm inner battery-to-U1 copper clearance; revised `CON-ARCH-007 AC-2`
   specifies 0.42 mm nominal after transverse oval-pad growth. Recompute from
   actual pads; nominal clearance does not establish swollen-pack insulation fit.
3. **Legacy qualification gap:** main physical scan validation accepted only
   `choc_v2`/`mx` modes and did not distinguish individual receptacles from bare
   MX solder pins. Legacy scan success must not authorize the selected receptacle
   assembly. The supplemental gate below closes this only when integrated into
   the bound raw-evidence path.
4. **Purchased-part gaps remain:** seller nominal open-bottom 3.00 mm length,
   1.45 mm barrel, 2.00 mm flange and 0.20 mm flange thickness do not specify
   tolerances, MX blade acceptance, contact-force or resistance limits. The
   1.60 mm trial PTH is not a proven production finished-hole tolerance.
   Exact protected pack/lead and J_BAT drill, seated controller gap, insulation,
   lead pull criteria, switch continuity/direction and full service access remain
   physical gates under `CON-ARCH-007`.
5. **Derived artifacts are baseline evidence:** existing housing/coupon/manifests
   predate the plate-lid and extended socket envelopes. Route fixes and a solid
   model alone do not qualify assembly, printed retention, torque, deflection,
   final power transitions or RF performance. Rebind canonical source hashes only
   after actual regeneration and verification; do not relabel historical outputs.

## Positive but limited inspection

Actual canonical pad nets and service rotations inspected through KiCad Python
match the intended local service topology on both halves: J_BAT1 pad 1 BAT+, pad
2 GND; POWER pad 1 BAT+, pad 2 NN_B+, pad 3 unconnected; U1 RAW NN_B+ and GND_C GND;
RESET pad 1 RST and pad 2 GND. POWER/RESET are mirrored 180 degrees on the right.
This confirms pad assignments, not actual routed connectivity or independently
qualified official physical controller/switch pin orientation. No schematic was
found in the canonical project paths. The `kicad-mcp` skill was read; no available
local `kc2-pcb-preflight` skill was found.

## Added automated safeguard

`tools/verify_kc2_mx_receptacle_evidence.py` and its test module implement a
supplemental `CON-ARCH-004 AC-3/AC-9` gate. Nine tests pass, including synthetic
positive evidence and rejection of missing/NaN limits, incompatible nominal
geometry, duplicate contact identities, partial replacement-cycle coverage,
out-of-limit force/resistance, missing retention and unverified provenance.
Synthetic numbers in the tests are explicitly not a production specification.

Integration must call `verify_mx_receptacle_evidence()` on the selected assembly's
bound raw scan subrecord. Pass `verified_artifact_paths` as a set produced by the
existing successful canonical-path/SHA-256 verifier, never a set copied from raw
JSON. `socket_specification`, `switch_specification` and `limits_source_artifact`
must reference those verified artifacts. Default missing provenance fails closed.
The main scan verifier must extend its exact schema and retain all old scan,
keycap, diode, housing and controller evidence requirements. Passing this helper
alone is not fabrication approval.

## Integration follow-up

The parent integrated the helper into `_physical_scan_metrics`. Independent
RED/GREEN tests then closed three additional binding gaps: exact semantic
document-path matching, equality of contact and raw-scan coupon identities, and
equality of the assembled MX switch MPN with both qualification `switch_mpn` and
the switch specification artifact's `part_number`. The contact and integration
modules now pass 15 tests together.

The existing full physical-evidence positive fixture is stale: its isolated
`test_physical_evidence_manifest_binds_files_hashes_and_thresholds` fails because
it provides neither MX contact documents/qualification nor the third receptacle
scan mode. This is expected fail-closed behavior requiring a complete fixture
update, not a reason to bypass the new checks. A combined 97-test run also had
stale DRC hash assertions and KiCad SWIG initialization errors; it is not passing
release evidence.

## Native test isolation repair

The SWIG cascade was independently minimized without loading canonical boards:
the controller-power negative test removed a `PCB_TEXT` using KiCad's public
`Remove` wrapper, which transfers ownership to the Python proxy. After local
objects were destroyed, subsequent footprint-plugin lookup returned an untyped
`SwigPyObject`. Plain footprint copy/destruction, `IsActionRunning`, and native
removal without ownership transfer did not reproduce this symptom.

A fresh-child-process regression reproduced the failure before the fix. The
negative test now blanks the required B-/GND text instead of deleting the native
object; absence of the required legend is still rejected by the same verifier.
All six source-only `V2FootprintTests` pass after this change. This repairs the
test harness, not PCB readiness; full release tests require a new run after
concurrent routing saves finish.

## Synthetic fixture refresh

The existing positive physical-evidence fixture now includes 24 scan conditions
(three assembly modes), three typed temporary hashed qualification documents,
the matched synthetic switch identity, three coupon keys across both halves,
both contacts and complete replacement-cycle coverage. Limits and observations
are explicitly synthetic and were not written to production evidence. Original
negative cases remain, with added missing-MX/partial-cycle rejection cases.

An isolated run passes the initial all-four-bundle positive validation, then
stops at the separately stale main housing-manifest exact-key contract, which
does not yet accept `mx_receptacle_stack`. The fixture does not remove that real
field to bypass the production-schema issue. Remaining negative cases need rerun
after the main housing schema is revised.
