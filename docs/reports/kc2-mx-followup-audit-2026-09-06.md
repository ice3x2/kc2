# First-order follow-up: machine review semantics

Requirements: OPS-ARCH-007 AC-1/AC-3/AC-4 and CON-ARCH-006. Independent scoped review, 2026-09-06.

## Defect reproduced and fixed

The previous release gate checked the bytes of bound verification reports but did not interpret their results. Three failing regression tests reproduced acceptance after updating only the affected report and its byte binding, while leaving engineering checkboxes true:

- Housing `digital_valid=false` with a known geometry error.
- A native Fusion archive/body-count verification blocker.
- A controller pin error in a board's detailed results despite an empty top-level error summary.

These are digital failures, not post-receipt measurements. The first-order phase exception must not hide them. This regression does not establish that the current PCB or CAD contains those synthetic errors.

`tools/prepare_kc2_first_order.py` now requires explicitly typed board/housing report references, validates their requirements and error fields, checks both board connectivity/DRC results and detailed error lists, and rejects failed housing digital/native results. Each report must carry raw `source_sha256` entries for the fixed inventory returned by `digital_report_inputs(role)`, matching both current source bytes and release bindings. Rebinding a changed source alone no longer refreshes an old machine report.

Evidence schema addition: `digital_reports: {board: <bound report path>, housing: <bound report path>}`. Both paths must also occur in `reviews.digital_verification`. Reports retain their normal verifier fields and add `source_sha256`; physical qualification blockers remain explicitly pending and are not converted to errors or passes.

## Verification

Initial RED: all three targeted mutation tests failed because the previous gate returned `eligible_to_build=true`.

GREEN: `python -B -m unittest tools.test_prepare_kc2_first_order tools.test_kc2_first_order_review_semantics -q` ran 19 tests successfully. Coverage includes the original package inventory/ZIP/DRC checks, typed/missing/malformed reports, hidden machine errors, stale report provenance, and an explicit positive case with physical acceptance still pending. Synthetic fixtures are not production qualification evidence.

Pre-edit tool/test copies are preserved under `.codex-tmp/first-order-semantics-backup-20260906T175407071`. No PCB, CAD, manufacturing output, or existing sealed package was changed by this review. Because the gate tool changed, the old package's tool binding is intentionally stale; a newly bound release is required.

## Limits and nominal mechanical claims

This is a report-semantic/provenance fix, not an independent recomputation of every native solid, component contact or keycap envelope. Machine reports must still be generated by their actual verifiers before provenance is recorded. Human component and visual reviews remain engineering evidence, not mathematically inferred from checkboxes.

The existing nominal fit report does not prove exact contact compatibility: socket diameter/contact tolerances and exact MX pin engagement remain unknown. Thirteen mounting heads overlap nominal keycap XY rectangles and one is tangent; these projections alone neither prove nor disprove full-travel collision. The conditional depressed-cap underside clearance and screw-length restrictions remain relevant. No physical insertion, soldering, torque, full-travel or powered/RF measurement is marked passed here. Known incompatibilities must still be corrected before order; unknowns require truthful first-product disclosure under OPS-ARCH-007.
